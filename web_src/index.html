FastOV Events ℹ️ Total FastOV rising-edge event counter. Increments once each time the FastOV supervisor changes from inactive to active. This includes any FastOV intervention: soft predictive clamp, hard predictive clamp, or measured-voltage hysteresis clamp. Use this to catch brief interventions that may be too short to notice in the live cap display.

What is normal: this value will usually keep increasing over time because it is a lifetime-style event counter. Slow growth is expected, especially during small RPM changes, load changes, or minor voltage corrections.

What is suspicious: fast growth during truly steady operation, especially if hard events are also increasing or if the system shows visible current or voltage pulsing. A high event rate at steady state can mean the FastOV thresholds are too aggressive, prediction is too jumpy, or the outer voltage loop still needs more tuning. ?
FastOV Soft Events ℹ️ Rising-edge counter for soft FastOV events only. A soft event means the predictive voltage logic entered the soft zone and started trimming the allowed current cap before voltage rose too far. This is the normal early-warning action of the FastOV supervisor.

What is normal: some soft events during transients, and occasional isolated events near the voltage target.

What is suspicious: frequent soft events during stable running with no meaningful overshoot. That usually means V_SOFT is too low, the prediction horizon is too aggressive, dv/dt is too noisy, or the outer CV loop is still pushing too hard near target. ?
FastOV Hard Events ℹ️ Rising-edge counter for hard FastOV events only. A hard event means the predictive hard zone or measured-voltage hysteresis clamp was triggered, causing a stronger current-cap reduction and instant downward setpoint action. Hard events should be uncommon in a well-tuned system.

What is normal: rare events during major (engine speed) transients or unusual operating conditions.

What is abnormal: repeated hard events, or any steady accumulation during normal settled charging. That usually means true overshoot is still occurring and the voltage loop is underdamped, too slow to pull down, or relying on FastOV as a primary control mechanism instead of a safety backstop. ?
Reset FastOV Event Counters ℹ️ Clears the soft, hard, and total FastOV event counters. Use after tuning changes to establish a fresh baseline for characterising false-fire rates.

How Anomaly Detection Works

What This System Does: The efficiency matrix learns the normal relationship between alternator field drive and output current across engine operating conditions. Once enough data is accumulated, it can detect when the alternator is producing significantly more or less current than it historically has under the same conditions — an early warning of problem such as brush wear, diode failure, belt slip, etc.

The Reference Matrix: Operating conditions are divided into bins along three axes — engine RPM, alternator case temperature, and field drive voltage (duty cycle × battery voltage). Every qualifying operating point is accumulated into the appropriate bin as a time-weighted running average, with minimum and maximum values tracked. This matrix persists across power cycles and accumulates forever. The more hours of operation, the more reliable each bin becomes.

Reference Finalization: Once the matrix has accumulated enough data across a sufficiently wide spread of operating conditions, the system automatically selects the best-populated bins as reference bins and freezes their values. These frozen values become the permanent baseline for anomaly detection. The selection algorithm favors bins that collectively span a wide range of RPM, temperature, and field drive — ensuring the reference is not built from a single narrow operating region. Until finalization occurs, the plot displays available data at reduced opacity with a "Low Confidence" label.

Two-Layer Anomaly Detection: Once reference bins are finalized, every qualifying operating point is checked against the reference for its current bin. Layer 1 is instantaneous — if the current output falls outside the stored reference min/max range (plus your configured tolerance), an error is counted immediately. This catches sudden failures like a broken belt or failed diode. Layer 2 is thermal — it accumulates a running average over approximately 90 seconds of operation in the same bin, then compares that settled average against the reference average. This catches gradual degradation that stays within the historical range on any individual reading but represents a sustained downward trend. Both layers check in both directions — unexpectedly high output is also flagged, as it can indicate a regulator fault or measurement error.

The Plot: The scatter plot shows field drive voltage on the horizontal axis and alternator output current on the vertical axis. When a finalized reference bin is active, a gray shaded band shows the historical min/max range and a solid gray line shows the historical average for that operating region. The red dot shows the live operating point. If the red dot sits inside the band, the alternator is performing normally. If it drifts outside, the band color and the warning banner below reflect the deviation. When operating in a populated but non-finalized bin, the band is shown faded with a Low Confidence label. When no reference data exists for the current conditions, only the red dot is shown.

Alarms and Reset: The session error count resets each power cycle. If the combined Layer 1 and Layer 2 error count exceeds the configured threshold in a single session, a warning banner appears on screen and optionally triggers the physical alarm output. The warning banner gives specific detail about which operating conditions triggered the anomaly, what the reference values were, and by how much the current output deviated. Use the Reset button only if you have replaced the alternator or made a mechanical change that invalidates the existing reference — it clears all accumulated matrix data and reference bins permanently.

PID Control Architecture

Two-Loop Control Architecture: The system uses two PID controllers running at different speeds. The inner loop runs fast — roughly 16 times per second — and continuously adjusts the alternator field duty cycle to hit a current target. The outer loop runs every 5 seconds and watches temperature. When temperature climbs toward the configured limit, the outer loop accumulates a thermal penalty that reduces the current the inner loop is allowed to chase. The two loops are cascaded: the outer loop constrains what the inner loop can do, but never interferes with how it does it.

RPM Cap Table: For each engine RPM range, you configure a hard ceiling based on your installation's physical limits — belt load, shaft stress, alternator and battery bank ratings. This ceiling is enforced after the thermal penalty is applied and is never exceeded regardless of thermal state. The ceiling can be entered as either a current limit (amps) or a power limit (kW) using the toggle above the table. In amps mode, the configured value is a fixed current ceiling. In kW mode, the firmware divides your power limit by live battery voltage on every control tick to derive the amp ceiling — so the mechanical load on the belt and shaft stays constant regardless of voltage sag or rise during charging.

Thermal Penalty: The outer temperature PID outputs a single number — thermal penalty in amps. Zero means no restriction. As temperature climbs toward the configured limit, the penalty grows and current is reduced. When the alternator cools, the penalty shrinks and current recovers. Because the penalty is relative rather than absolute, it transfers intelligently across RPM changes. A 20-second derivative window allows the outer loop to react to rising thermal momentum before the setpoint is actually reached.

Three-Stage Charging: The system implements a CC/CV/Float charging cycle, with an optional Idle mode after Absorption for lithium longevity.

In bulk stage, the voltage loop is off and the system charges at the maximum thermally allowed current from the RPM table. This continues until battery voltage has been held at the bulk voltage target continuously for the configured hold time — a debounce that prevents transient voltage spikes from triggering a premature transition.

In absorption stage, the voltage loop engages and holds the battery at the absorption voltage. The battery itself now dictates how much current it accepts — current tapers naturally as the battery fills. The system exits absorption when charge current has dropped to or below the configured tail current for the required hold period, confirming the battery is genuinely full. A safety timeout forces a transition to float if tail current is never reached.

In float stage, the voltage loop holds the battery at the lower float voltage. After the minimum float time has elapsed, the system monitors for voltage sag or sustained discharge current. If either condition persists for the rebulk debounce period, or if float duration expires, bulk charging restarts — subject to SoC blocking if SoC data is available. If Use Float is OFF, the system skips float entirely and enters Idle after Absorption, charging again only when rebulk criteria are met.

Stability and Recovery: All mode transitions are bumpless: the inner PID integrator is aligned to the current operating point before switching. If the temperature sensor goes stale, the outer loop freezes its last penalty value until fresh data returns. The anti-windup system ensures the outer loop's integrator stays correctly positioned — parked near any tighter non-thermal constraint when thermals are not the binding limit, and free to drive the penalty upward the moment temperature demands it. Independent hard protection layers — warning ramp-down and critical immediate shutdown via GPIO4 — operate completely separately from the PID and remain active regardless of PID state. Any fault that interrupts charging will restart from bulk when charging resumes, never mid-cycle.

How to Tune the PID Controller

Overview: This system uses a three-phase tuning process. The goal is to tune the core PID loop first, then verify it handles the rate limiters gracefully with anti-windup tracking. Tuning is done in bulk stage — absorption and float use the same inner loop but with the voltage controller constraining the setpoint, so a well-tuned bulk response carries through automatically.

Phase 1 - Core Loop Tuning (Unrestricted):
Set both slew limiters to very high values to effectively disable them:
• Setpoint Rise Rate: 1000 A/s
• Setpoint Fall Rate: 1000 A/s
• Duty Ramp Rate: 1000 %/s
Enable Tuning Mode and observe the response on plots. Tune Kp, Ki, and Kd until you get well-damped step responses with minimal overshoot (10–20%) and fast settling time (2–4 seconds).

Phase 2 - Actuator Slew + Anti-Windup Tuning:
Enable the actuator slew limiter by setting Duty Ramp Rate to a realistic value (typically 10–30 %/s). Keep setpoint slew limiters high (1000 A/s). Run tuning mode again and watch for overshoot after transitions. If you see overshoot after the duty ramp catches up, increase PID Tracking Gain from its default until the overshoot disappears.

Phase 3 - Production Verification:
Set Setpoint Rise Rate and Setpoint Fall Rate to your desired production values (typically 5–20 A/s rise, 20–50 A/s fall). Run tuning mode one final time to verify the loop remains stable and well-behaved.

Tuning Philosophy for Cruising:
Run tests at moderate RPM within your typical cruising range. A slower, well-damped loop (4–6 second settling time) is preferable to a fast loop that causes harsh load transitions. The multi-layer safety systems protect your equipment — you don't need the PID to react instantly. Smooth and stable beats fast and harsh.

Typical Starting Values: Kp = 0.3, Ki = 1.5, Kd = 0.0, Tracking Gain = 2.0–4.0

How It Works

Rebulk: The system always begins in Bulk when charging is enabled. It returns to Bulk from Float or Idle if battery voltage drops below Rebulk Voltage or net discharge current exceeds Rebulk Current Threshold — continuously for Rebulk Debounce Time. The timer resets if the condition clears before the debounce expires. If Float Duration expires, the system also returns to Bulk. If SoC data is available, it will suppress rebulk when the battery is near full, or permit it when SoC has dropped below the allow threshold — but SoC alone cannot trigger rebulk; voltage, current, or timeout criteria must also be met.

Bulk: The system pushes maximum thermally(and otherwise)-allowed current from the RPM table. Bulk ends once battery voltage has remained continuously at or above Bulk Voltage for Bulk Voltage Debounce Time.

Absorption: The voltage loop holds the battery at Absorption Voltage. Current is no longer commanded — the battery dictates how much it accepts and it tapers naturally as the battery fills. Absorption ends when current drops to or below Tail Current continuously for Absorption Completion Time. If tail current is never reached, a safety exit occurs after Absorption Timeout.

Float (if enabled): The system holds the battery gently at Float Voltage. After Minimum Float Time has elapsed, rebulk criteria are evaluated. If Float Duration expires, the system also returns to Bulk. If Use Float is OFF, charging stops after Absorption and the system idles until rebulk criteria are met — better for lithium longevity in cycling applications.
